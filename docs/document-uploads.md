# 文件原件归档与重复上传复用

适用于 PDF/DOCX 上传接口。手工输入文本的接口仍按原逻辑新增文档。

## 用户可见行为

- 首次上传：校验文件、提取文本、保存原件、生成向量并入库。
- 相同字节的文件重复上传：复用原文档 ID、原标题和原件名，返回 `reused: true`。改文件名或另填标题不会新建副本，也不会修改原标题。
- 文件内容发生变化：作为新文档入库。这里按 SHA-256 文件字节指纹去重，不保证内容相近或重新导出的 PDF/DOCX 能去重。
- 列表中有原件的文档显示“下载原件”。下载接口沿用现有 Bearer Token 鉴权；没有原件的历史文档或手工文本没有此按钮。
- 删除文档：删除当前索引内向量和上传记录；原件未被其他索引记录引用时一起删除。之后再次上传会重新入库。
- 普通重启不会重新解析或生成文档向量。重复上传不命中旧记录中的已删除文档。

## 存储位置

默认 `DOCUMENT_STORAGE_DIR=./data/documents`，可通过环境变量配置。

```text
data/documents/
  originals/<文件SHA-256>.pdf 或 .docx
  uploads.sqlite3
  uploads.lock
```

原件文件名由服务端生成，上传文件名只作为元数据保存，不能控制磁盘路径。原件先写临时文件再原子替换。`data/` 已被 Git 忽略。Docker API 部署已有 `./data:/app/data` 挂载，可保存这些文件；本机运行时需从项目根目录启动，以保持相对目录一致。

备份和恢复时同时保留 Milvus 数据、原件和上传记录。单独保留原件不会自动恢复向量；单独丢失上传记录会失去重复上传判断。

## 去重范围与并发

去重键包含文件 SHA-256，以及数据库目标、Embedding 配置和解析/切分版本生成的索引身份。更换模型、数据库集合或处理版本不会误用旧向量。修改解析/切分规则时需同步调整 `app/services/document_uploads.py` 的 `PIPELINE_REVISION`；更换 Milvus 模型/维度还须遵守现有集合兼容性检查。

当前为本地单机实现，使用操作系统文件锁串行处理同一原件目录的上传和删除，支持同机多个后端进程。另一个请求正在处理时返回 HTTP 409，请稍后重试。尚不是多机分布式任务队列。

入库开始前记录 `indexing`，成功后记录 `ready`。普通异常会尝试补偿已完成的入库并清理原件/记录，让请求可以重试。进程意外退出会释放操作系统锁，但可能留下 `indexing` 记录；此时重复上传返回 `DOCUMENT_UPLOAD_INTERRUPTED`，不会盲目再次计费。需核对 Milvus 中是否完成写入，再修复记录或清理对应残留后重试。这不是横跨文件系统、SQLite 和 Milvus 的原子事务，数据库通信故障下的写入结果也可能需要人工核对。

## 接口变化

- 上传响应增加 `reused`：是否复用已有入库结果。
- 文档摘要增加 `original_filename`：有已归档原件时返回文件名，否则为 null。
- `GET /api/v1/documents/{doc_id}/original`：鉴权下载原件。
- 原有上传大小、格式和解析上限保持生效。
