# 会话上下文与长期记忆

本模块解决三类问题：同一会话的追问缺少前文、跨会话偏好无法沿用、历史和记忆无限增长。使用项目自定义逻辑、SQLite 和 aiosqlite，没有使用 Mem0/Memobase，也没有用模型生成或训练记忆。

## 一次请求的执行顺序

1. ChatService 按 session_id 获取进程内 asyncio.Lock，校验会话所属 user_id。
2. 从 SQLite 读取该会话已有消息；当前问题尚未追加，避免重复进入历史。
3. context.py 构建最近消息窗口和较早用户原话的抽取式摘要。对“那需要谁审批”等匹配规则的追问，补充最近独立用户话题，得到检索 query。
4. 保存当前消息；从明确的用户陈述中提取长期记忆，并读取本次相关记忆。
5. 原始问题用于判断当前明确意图；必要时利用补全主题识别 RAG 分支。知识检索使用补全后的 query；历史中的工具请求不会被重新执行。
6. 模型输入中包含有角色标记的最近消息、较早用户摘录、长期记忆和当前问题；RAG 另外加入本次证据，Tool 另外加入工具结果。
7. 保存助手回答及最终运行快照。SSE 的 done 事件在保存完成后发送。

普通和流式接口共用 build_context、记忆提取/检索及提示词格式化逻辑。普通接口仍用 StateGraph；流式接口仍是共享节点组件的手动分支，不宣称已统一成 LangGraph 原生事件流。

## 三层上下文

| 层 | 默认限制 | 保存/使用方式 |
| --- | --- | --- |
| 最近对话 | 最近 6 条消息；正文累计 6000 字符；单条 2000 字符 | SQLite messages 中取出，带 user/assistant 角色作为 JSON 背景资料注入模型 |
| 较早对话摘录摘要 | 1200 字符 | 保留较早用户原话的有界摘录，不把助手回答当作已确认事实；超出保留窗口的消息删除前更新 sessions.context_summary |
| 用户长期记忆 | 最多 100 条/用户；每条 320 字符；本次最多 5 条 | SQLite user_memories；跨会话按 user_id 读取 |

这是字符预算，不是精确 Token 计数。当前问题沿用 API 的 4000 字符限制，记忆和历史各有预算，检索上下文沿用 Top-3/片段截断限制；没有声称支持任意模型的精确上下文窗口计算。较早摘要是去重后的原文摘录，不是 LLM 语义摘要，长对话会有信息损失。单个近期长消息可能被截断。

模型收到的结构示意：

```text
system：当前分支规则
user：
  JSON背景资料（earlier_user_excerpts / recent_messages / user_memories）
  用户当前问题
  知识库片段或工具结果（视分支）
```

过去的消息作为带角色字段的数据注入，而不是提升为 system 指令。提示词要求当前用户要求优先于旧偏好、指代不明确时澄清；这不是完备的提示注入防护。

## 长期记忆写入与更新

- 自动提取五种类型：profile、preference、goal、project_fact、decision。
- 按句子/分句提取并限制长度，不再把包含无关问题的整个消息直接复制成每一种记忆。
- 自动偏好提取要求“以后、我喜欢、我希望”等信号；“这次、本次、暂时”不提升为长期偏好。
- 语言和详略采用两个固定槽：response_language、response_detail。例如“以后用中文详细解释”拆为“回答语言：中文”和“回答详略：详细”。后续“以后简短回答”更新详略槽，语言保留。
- 每个槽在同一用户下最多一条，通过事务和唯一索引避免并发重复；更新只影响该用户。
- 手动添加偏好也识别这两类标准字段；同时包含两个字段时会保存两条，创建接口的 memory 返回最后一条，列表接口返回全部。
- 其他事实采用规范化空白后的同类型、同文本去重，不做任意语义冲突判断或通用语义合并。
- 旧版本数据库第一次增加 slot 列时，会转换能识别的旧语言/详略偏好；按更新时间顺序处理，以最后值为准，并保留原时间戳。含这两类字段的旧混合偏好会被标准字段替换，未识别的自由文本偏好保留。
- 密钥/密码等模式匹配在长期记忆提取及手动写入前拒绝；聊天记录和快照仍可能含原始输入，不宣称全库脱敏。

## 读取、过期和容量

读取优先带上语言/详略槽（最多两条），其余名额按 0.60×向量相似度 + 0.25×词项重合度 + 0.15×重要度评分，总计最多五条。默认向量仍是 Hash Embedding，不代表真实语义能力；记忆评分与文档的 BM25/RRF 是不同逻辑。

每次用户的记忆写入、查询、列表操作都会清理超过 180 天未更新的记录；不是后台定时任务，也不会因读取而续期。容量超限时优先淘汰低重要度、旧记录，保留刚写入的记录。每个会话最多保留 100 条原始消息和 30 个最终快照。默认会删除超限记录，部署已有数据前请备份 SQLite 文件。

这些是每用户/每会话限制，用户数和会话数没有全局配额或自动过期；数据库物理文件也不保证立即缩小。LangGraph MemorySaver 只用于当前运行，在普通请求完成或失败后释放该 thread 的内存检查点；重启后的上下文从 SQLite 重建，不支持任意中间节点续跑。

## 复现与边界

```powershell
python -m pytest tests/test_memory_context.py -q
python -m pytest -q
```

专项覆盖：普通/SSE 追问检索、前轮人物信息进入模型输入、真实 HTTP 适配器请求体、跨会话偏好、语言/详略更新、短期要求过滤、敏感信息过滤、容量和过期、摘要及原始记录截断、旧表迁移、并发首次建表、同会话串行、跨用户会话拒绝、真实本地 BM25/RRF 追问检索、内存图状态释放。

这些测试使用本地 Hash Embedding、可控模型替身及 Mock HTTP，验证的是数据流和管理机制；没有进行外部 LLM 的真实代词理解准确率评测。规则补全只覆盖常见前缀，多个指代对象、复杂话题切换可能需要澄清或后续接入受约束的模型改写。

user_id 仍是客户端传入的开发标识；会话归属检查不等于登录认证。管理读取 API 仍面向本地开发，生产前需要真实身份认证及每个读取接口的权限校验。同会话 asyncio.Lock 仅在单进程内生效，多 worker 部署还需数据库/分布式并发控制。
